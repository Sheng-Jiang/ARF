# ARF code review — 21 Oct 2026

Review of the recent agent work (`fef2fef` — Opportunity Alpha state machine,
5-step IDR schema, Gemini showcase stack), focused on `arf/db.py`,
`arf/agent/thesis.py`, and `arf/agent/schemas.py`.

**Status:** 5 findings fixed (correctness blockers); 6 remain open. A follow-up
pass after review of the first fixes corrected four regressions they introduced
(typed JSON, NULL gate fields, stage normalization, explicit clears).

---

## Fixed in this pass

### 1. `upsert_idr` erased stored fields on partial updates — FIXED

`INSERT OR REPLACE` rebuilt every column from dict defaults, so a partial write
(e.g. recording `human_pm_decision`) reset `gate_verdict` from `BLOCKED_FROTH`
to `PASSED`, `recommended_action` to `MONITOR`, and wiped
`invalidation_criteria`. Verifying the audit record destroyed it. Furthermore,
calling `upsert_idr(conn, idr.model_dump())` emitted `human_pm_decision: None`,
which risked overwriting human PM sign-offs.

**Fix** (`arf/db.py:1279`): updates now read the stored row and merge — a key
absent from the update keeps its stored value, `created_at` is preserved, and
existing rows are updated in place rather than replaced. An explicit `None` is
an intentional clear (so a PM sign-off can be retracted); callers passing a full
`model_dump()` must use `exclude_unset=True`, which the compiler now does.
String values are safeguarded from becoming the literal string `"None"`. Both
the storage column names and the Pydantic field names
(`observed_metrics` / `observed_metrics_json`, …) are accepted.

**Tests:** `tests/test_db.py::test_partial_update_preserves_stored_fields`,
`tests/test_db.py::test_model_dump_does_not_erase_pm_annotations`,
`tests/test_db.py::test_explicit_none_retracts_pm_annotation`.

### 2. A new IDR regressed advanced lifecycle state — FIXED

`upsert_idr` unconditionally called `update_opportunity_stage` with the IDR's
`thesis_formulated` stage. Re-running card generation on a `harvested` name
silently reopened it as an active thesis.

**Fix** (`arf/db.py:1246`, `arf/db.py:1420`): stage writes are now monotonic
along the `OpportunityStage` lifecycle; a lower rank keeps the existing stage
while still refreshing `latest_idr_id` and metadata. Terminal stages
(`harvested`, `invalidated`) can no longer be rolled back by card generation.
Stage comparison is case-insensitive and the value is normalized before it is
stored, so `"HARVESTED"` cannot leak into the column and defeat
`query_opportunity_states(stage="harvested")`.

**Tests:** `tests/test_db.py::test_new_idr_does_not_regress_advanced_stage`,
`tests/test_db.py::test_stage_rank_and_json_dumps_safe`,
`tests/test_db.py::test_stage_normalized_before_storage`.

### 3. `QuantFactorSnapshot(**)` crashed on NULL technicals — FIXED

`get_stock_quant_profile` LEFT JOINs `technical_metrics`, so a name without
technical coverage (new HK IPOs, per-ticker fetch failures) returned
`ma_bullish=None`, which pydantic rejects for `bool`. IDR compilation died
before the card was built.

**Fix** (`arf/agent/thesis.py:92`): a `_quant_snapshot` helper coerces NULL
booleans to their schema defaults (`False` = not flagged / not bullish),
normalizes `as_of_date` to string (treating `NaT`/NaN as missing rather than
storing the literal strings `"NaT"`/`"nan"`, which DuckDB rejects as a DATE),
and guards the required string fields. Used for both `observed_metrics` and the
card's `quant_profile`.

**Test:** `tests/test_agent.py::test_compile_idr_without_technical_metrics`.

### 4. `_json_dumps_safe` crashed on date / numpy objects — FIXED

`QuantFactorSnapshot.as_of_date` allows `str | date`, and numeric profiling
arrays frequently carry NumPy scalars (`np.int64`, `np.float64`). Python's
`json.dumps` threw `TypeError` on these non-primitive objects.

**Fix** (`arf/db.py:1148`): `_json_dumps_safe` recursively converts values to
JSON-native types: NumPy scalars and `Decimal` become Python numbers, dates
become ISO strings, non-finite floats become `null`, and dict keys are
normalized (`default=` is never applied to keys). Numbers stay numbers — an
earlier `default=str` version silently stored `np.int64(4)` as the string
`"4"`. `None` is stored as JSON `null`, not `[]`, so object-shaped
`observed_metrics_json` keeps its shape; list columns pass an explicit `[]`.

**Test:** `tests/test_db.py::test_stage_rank_and_json_dumps_safe`,
`tests/test_db.py::test_json_columns_preserve_types_and_shapes`.

### 5. `_json_dumps_safe` was not date/numpy safe; partial commit on failure — FIXED

The serialization half is covered by finding 4. The partial-commit half:
`upsert_thesis` committed before `upsert_idr` ran, so a serialization failure
left a committed card with a dangling `idr_id` and no audit record.

**Fix** (`arf/agent/thesis.py:300`): the IDR is persisted first. If the card
write then fails, the result is an IDR without a card, which is recoverable;
the reverse is a dangling audit reference.

## Additional hardening (follow-up review)

These were regressions or gaps in the first pass, now fixed and tested:

- **Gate fields no longer default to a pass** (`arf/db.py:1337`). A record
  written without `gate_verdict`/`hurdle_met` stores NULL, so "gate never ran"
  is distinguishable from "gate passed".
- **Stages are normalized before storage** (`arf/db.py:1246`), closing the
  mixed-case variant of finding 2.
- **An IDR with an empty name cannot overwrite the stored friendly name**
  (`arf/db.py:1442`); the merge in `update_opportunity_stage` handles fallbacks.
- **Explicit `None` clears PM annotations** while `exclude_unset=True` keeps a
  recompiled card from clearing them; both directions are tested.

## Open findings

### High

6. **WACC hurdle only enforced for `garp_value`** — `arf/agent/thesis.py:211`.
   A `long_opportunity` with ROE far below cost of equity passes G3 and gets
   `BUY_ZONE` while the same IDR stores `hurdle_met=False`.

### Medium

7. **G3 verdicts are written but never read** — `arf/agent/thesis.py:207`.
   A froth-flagged long still renders as "🟢 战略做多" in the webapp because it
   keys off `thesis_type`, not `gate_verdict`.

8. **Invalidation gate is a 15-char length check** — `arf/agent/thesis.py:216`.
   The design doc specifies `< 20`, and character count does not verify
   quantitative content; `"no invalidation set"` passes.

9. **`update_opportunity_stage` cannot clear fields** — `arf/db.py:1375`.
   `new or old` merge means an explicit `""` silently keeps the stale value
   (e.g. an entry zone on an invalidated name).

10. **Empty bull/bear fallback and unguarded `.split`** — `arf/agent/thesis.py:231`.
    A missing `bull_case` yields `'[""]'`; a JSON array response raises
    `AttributeError` and fails card generation.

11. **Dead enum members / unimplemented state machine** — `arf/agent/schemas.py:23`.
    `BLOCKED_VALUATION_STRETCH`, `DecisionAction.HARVEST/INVALIDATE`, and
    `QUALIFIED`/`UNDER_REVIEW`/`COMMITTEE_PENDING` have no emitting code path.
    The advertised Max P/S gate and 8-stage lifecycle are unreachable.

## Common thread

`upsert_idr` (findings 1, 2, 9) and the G3 gate in `thesis.py`
(findings 6, 7, 8, 10) are the hotspots. Findings 6 and 7 are the ones that can
put a wrong recommendation in front of a user; the rest are audit-integrity and
robustness issues.
