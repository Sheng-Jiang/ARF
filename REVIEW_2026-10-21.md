## Fixed in this pass

### 1. `upsert_idr` erased stored fields on partial updates — FIXED

`INSERT OR REPLACE` rebuilt every column from dict defaults, so a partial write
(e.g. recording `human_pm_decision`) reset `gate_verdict` from `BLOCKED_FROTH`
to `PASSED`, `recommended_action` to `MONITOR`, and wiped
`invalidation_criteria`. Verifying the audit record destroyed it. Furthermore,
calling `upsert_idr(conn, idr.model_dump())` emitted `human_pm_decision: None`,
which risked overwriting human PM sign-offs.

**Fix** (`arf/db.py:1202`): updates now read the stored row and merge — keys
absent or with `None` values keep their stored value, `created_at` is preserved,
and existing rows are updated in place rather than replaced. String values are
safeguarded from becoming the literal string `"None"`. Both the storage column
names and the Pydantic field names (`observed_metrics` / `observed_metrics_json`, …)
are accepted.

**Tests:** `tests/test_db.py::test_partial_update_preserves_stored_fields`,
`tests/test_db.py::test_model_dump_does_not_erase_pm_annotations`.

### 2. A new IDR regressed advanced lifecycle state — FIXED

`upsert_idr` unconditionally called `update_opportunity_stage` with the IDR's
`thesis_formulated` stage. Re-running card generation on a `harvested` name
silently reopened it as an active thesis.

**Fix** (`arf/db.py:1184`, `arf/db.py:1322`): stage writes are now monotonic
along the `OpportunityStage` lifecycle; a lower rank keeps the existing stage
while still refreshing `latest_idr_id` and metadata. Terminal stages
(`harvested`, `invalidated`) can no longer be rolled back by card generation.
Stage comparison is case-insensitive.

**Tests:** `tests/test_db.py::test_new_idr_does_not_regress_advanced_stage`,
`tests/test_db.py::test_stage_rank_and_json_dumps_safe`.

### 3. `QuantFactorSnapshot(**)` crashed on NULL technicals — FIXED

`get_stock_quant_profile` LEFT JOINs `technical_metrics`, so a name without
technical coverage (new HK IPOs, per-ticker fetch failures) returned
`ma_bullish=None`, which pydantic rejects for `bool`. IDR compilation died
before the card was built.

**Fix** (`arf/agent/thesis.py:92`): a `_quant_snapshot` helper coerces NULL
booleans to their schema defaults (`False` = not flagged / not bullish),
normalizes `as_of_date` to string, and guards the required string fields. Used
for both `observed_metrics` and the card's `quant_profile`.

**Test:** `tests/test_agent.py::test_compile_idr_without_technical_metrics`.

### 4. `_json_dumps_safe` crashed on date / numpy objects — FIXED

`QuantFactorSnapshot.as_of_date` allows `str | date`, and numeric profiling
arrays frequently carry NumPy scalars (`np.int64`, `np.float64`). Python's
`json.dumps` threw `TypeError` on these non-primitive objects.

**Fix** (`arf/db.py:1146`): `_json_dumps_safe` passes `default=str` to `json.dumps`,
allowing dates, datetimes, and NumPy values to serialize without errors.

**Test:** `tests/test_db.py::test_stage_rank_and_json_dumps_safe`.

## Open findings

### High

5. **WACC hurdle only enforced for `garp_value`** — `arf/agent/thesis.py:211`.
   A `long_opportunity` with ROE far below cost of equity passes G3 and gets
   `BUY_ZONE` while the same IDR stores `hurdle_met=False`.

### Medium

6. **G3 verdicts are written but never read** — `arf/agent/thesis.py:207`.
   A froth-flagged long still renders as "🟢 战略做多" in the webapp because it
   keys off `thesis_type`, not `gate_verdict`.

7. **Invalidation gate is a 15-char length check** — `arf/agent/thesis.py:216`.
   The design doc specifies `< 20`, and character count does not verify
   quantitative content; `"no invalidation set"` passes.

8. **`update_opportunity_stage` cannot clear fields** — `arf/db.py:1375`.
   `new or old` merge means an explicit `""` silently keeps the stale value
   (e.g. an entry zone on an invalidated name).

9. **Empty bull/bear fallback and unguarded `.split`** — `arf/agent/thesis.py:231`.
   A missing `bull_case` yields `'[""]'`; a JSON array response raises
   `AttributeError` and fails card generation.

10. **Dead enum members / unimplemented state machine** — `arf/agent/schemas.py:23`.
   `BLOCKED_VALUATION_STRETCH`, `DecisionAction.HARVEST/INVALIDATE`, and
   `QUALIFIED`/`UNDER_REVIEW`/`COMMITTEE_PENDING` have no emitting code path.
   The advertised Max P/S gate and 8-stage lifecycle are unreachable.

## Common thread

`upsert_idr` (findings 1, 2, 8) and the G3 gate in `thesis.py`
(findings 5, 6, 7, 9) are the hotspots. Findings 5 and 6 are the ones that can
put a wrong recommendation in front of a user; the rest are audit-integrity and
robustness issues.
